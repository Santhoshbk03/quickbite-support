## 0. Conventions

**Priority tags.** Every field carries one:

| Tag    | Meaning               | Frontend behaviour if missing                                                                        |
| ------ | --------------------- | ---------------------------------------------------------------------------------------------------- |
| **P0** | Required.             | Treated as a contract violation. The response fails with `contract_violation`, which is loud in dev. |
| **P1** | Strongly recommended. | The UI section that depends on it hides cleanly.                                                     |
| **P2** | Nice-to-have.         | Silently degraded or client-side fallback.                                                           |

**Wire format.**

- JSON, UTF-8, `snake_case` keys. The frontend uses the same names, with no mapping layer to drift.
- Timestamps are ISO 8601 with a zone: `2026-09-14T14:12:07.512Z` or `…+00:00`. Python's `datetime.isoformat()` on an aware datetime is fine.
- Money is an integer in minor units plus an ISO 4217 code: `{"amount_minor": 13000, "currency": "INR"}` = ₹130.00. Never floats.
- IDs are opaque strings, 1–128 chars. Suggested prefixes: `conv_`, `msg_`, `tc_`. Chunk ids are your Chroma ids verbatim.
- **Null vs absent.** For P1/P2 fields, `null` and "key absent" mean the same thing, so a Pydantic `Optional[X] = None` works as-is. A P0 field marked _nullable_ must be **present**, possibly as `null`.
- **Forward compatibility.** The server may add fields and event types at any time. The client ignores unknown fields and unknown SSE event types. Renaming or removing a field is breaking and needs a `contract_version` bump.

**Base URL.** `NEXT_PUBLIC_API_URL`. It may include a path prefix (e.g. `https://api.example.com/v1`). All paths below are relative to it.

## 1. `POST /chat`

### 1.1 Request

| Header                           | Priority | Notes                                                                                      |
| -------------------------------- | -------- | ------------------------------------------------------------------------------------------ |
| `Content-Type: application/json` | P0       |                                                                                            |
| `Accept: text/event-stream`      | —        | Always sent by the client.                                                                 |
| `X-Request-Id`                   | P2       | Client may send one. The server should echo it in the response header and in error bodies. |

```json
{
  "conversation_id": "conv_k3Jd9wQm",
  "message": {
    "id": "msg_u_5fT1",
    "content": "Do I get anything for the delay?"
  },
  "history": [
    {
      "role": "user",
      "id": "msg_u_4aR0",
      "content": "Where's my order QB-48213? It's been almost an hour."
    },
    {
      "role": "assistant",
      "id": "msg_7Hc2pQ",
      "content": "Let me pull up order **QB-48213**.\n\nYour order from **Dosa Republic** is **out for delivery** …",
      "tool_calls": [
        {
          "name": "lookup_order",
          "arguments": { "order_id": "QB-48213" },
          "result": { "order_id": "QB-48213", "status": "out_for_delivery", "…": "…" }
        }
      ]
    }
  ],
  "options": { "regenerate_of": null }
}
```

| Field                   | Type                          | Priority | Notes                                                                                                                                |
| ----------------------- | ----------------------------- | -------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| `conversation_id`       | string                        | P0       | Client-generated and stable across a conversation. **Use it as the Langfuse `session_id`.**                                          |
| `message.id`            | string                        | P0       | Client-generated id of the new user turn. Attach it to trace metadata.                                                               |
| `message.content`       | string, 1–4000 chars          | P0       | Already trimmed by the client.                                                                                                       |
| `history`               | `HistoryMessage[]`, max 50    | P0       | Prior turns, oldest first, **excluding** `message`. May be `[]`.                                                                     |
| `history[].role`        | `"user" \| "assistant"`       | P0       |                                                                                                                                      |
| `history[].content`     | string                        | P0       | Assistant content includes the `[n]` citation markers exactly as generated.                                                          |
| `history[].id`          | string                        | P2       |                                                                                                                                      |
| `history[].tool_calls`  | `{name, arguments, result}[]` | P1       | Only on assistant turns. Lets a follow-up like "do I get anything for the delay?" reason over the order the model already looked up. |
| `options.regenerate_of` | string \| null                | P2       | Id of the assistant message being regenerated. Tag the trace with it.                                                                |

**Server obligations**

- **MUST** treat each request as self-contained: `history` + `message` is everything. There is no "create conversation" call.
- **SHOULD** apply its own history budget before prompting (e.g. the last N messages or a token cap). Truncation is the server's decision.
- **SHOULD** rewrite follow-up questions into a standalone query before embedding, and report it in `retrieval.standalone_query`. "Can I just cancel it instead?" embeds terribly on its own.

### 1.2 Conversation & history semantics

**The client owns history.** This is the chosen design, for three reasons:

1. The backend stays stateless. Nothing is lost when a free-tier instance sleeps or restarts, and it scales horizontally for free.
2. The frontend already persists conversations locally for the history rail.
3. Demo replay needs no server.

| Action               | What the client does                                                                                                        | What the server does                                                                                                                                   |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **New conversation** | Mints a new `conversation_id` and sends `history: []`.                                                                      | Treats an unseen id as a new session. No endpoint needed.                                                                                              |
| **Follow-up**        | Same `conversation_id`, full `history`.                                                                                     | Rewrites the query and retrieves.                                                                                                                      |
| **Regenerate**       | Same `conversation_id` and same `message` (same id). `history` excludes the discarded answer. Sets `options.regenerate_of`. | Produces a new assistant `message_id`.                                                                                                                 |
| **Stop generating**  | Aborts the HTTP request.                                                                                                    | **SHOULD** detect the disconnect (generator cancellation / `await request.is_disconnected()`), stop calling the LLM, and close the trace as cancelled. |

**Trust boundary.** Client-sent history is untrusted input. `history[].tool_calls[].result` is context for the model, never an authority. Nothing has side effects today (`lookup_order` is read-only). If you add a tool that does something, re-fetch server-side.

> **Alternative (not chosen): server-owned history.** The request would carry only `conversation_id` + `message`. The server
> loads and stores turns (Redis/Postgres) and exposes `GET /conversations/{id}` for rehydration.
> _Pros:_ tamper-proof history, smaller payloads, cross-device sync. _Cons:_ needs a datastore, breaks on ephemeral
> hosts, and complicates regenerate/branching. **Switching later changes only `HttpChatClient`'s request builder.**
> The `ChatClient` interface the UI depends on is identical either way.

### 1.3 Status codes

Errors **before** the stream starts are normal JSON responses with the [error envelope](#5-errors). Once a `200` and
headers have been flushed, errors are delivered **in-band** as an `error` event. The status line cannot change after that point.

| Status | `error.code`             | Retryable | When                                                                                |
| ------ | ------------------------ | --------- | ----------------------------------------------------------------------------------- |
| `200`  | —                        | —         | Stream started.                                                                     |
| `400`  | `invalid_request`        | no        | Malformed JSON.                                                                     |
| `413`  | `payload_too_large`      | no        | Body over 256 KB.                                                                   |
| `415`  | `unsupported_media_type` | no        | Not `application/json`.                                                             |
| `422`  | `validation_error`       | no        | Schema violation. Populate `details[]`.                                             |
| `429`  | `rate_limited`           | yes       | Per-client limit. Send the `Retry-After` header (seconds) **and** `retry_after_ms`. |
| `500`  | `internal_error`         | yes       | Unexpected failure before streaming.                                                |
| `503`  | `service_unavailable`    | yes       | Warming up / index not loaded. Send `Retry-After`.                                  |

### 1.4 Stream framing

**Response headers (P0)**

```http
HTTP/1.1 200 OK
Content-Type: text/event-stream; charset=utf-8
Cache-Control: no-cache, no-transform
X-Accel-Buffering: no
```

`no-transform` and `X-Accel-Buffering: no` stop proxies (nginx, some PaaS routers, compression middleware) from buffering the stream into one blob.
Do not gzip this response.

**Event frame**

```text
event: <type>
id: <seq>
data: <json>

```

Framing rules (all **MUST**):

1. `data` is **exactly one line** of compact JSON. `json.dumps` / `model_dump_json()` already escape newlines. Never split one event across multiple `data:` lines.
2. The JSON object always contains `"type"`, equal to the `event:` value. The client dispatches on `data.type`. The `event:` line is for curl/devtools readability.
3. `id` is a per-response sequence number: starts at `0`, strictly increasing. `Last-Event-ID` resumption is **not supported**. A dropped connection loses the response and the client offers retry.
4. A blank line terminates each event. The client accepts `\n\n` and `\r\n\r\n`.
5. **Heartbeat.** If 10 s pass with nothing sent, send the SSE comment `: keep-alive\n\n`. The client ignores comments. This stops idle-timeout proxies from killing slow generations.
6. Flush after every event. Don't batch deltas beyond what the model provider already does.
7. **Exactly one terminal event**, `message.end` or `error`. Close the stream immediately after it. If the stream closes without one, the client reports `stream_interrupted`.

### 1.5 Event types

| `type`             | Priority | Payload key | Purpose                                                                  |
| ------------------ | -------- | ----------- | ------------------------------------------------------------------------ |
| `message.start`    | P0       | _(flat)_    | Opens the response and assigns the assistant `message_id`.               |
| `status`           | P2       | _(flat)_    | Pipeline phase for the thinking indicator.                               |
| `retrieval`        | P0       | `retrieval` | Every retrieved chunk with distances. Feeds citations and the inspector. |
| `message.delta`    | P0       | `delta`     | A text fragment.                                                         |
| `citation`         | P2       | _(flat)_    | The model just cited chunk `[n]`.                                        |
| `tool_call.start`  | P0 †     | `tool_call` | A tool invocation has begun.                                             |
| `tool_call.result` | P0 †     | `tool_call` | The tool finished (success or error).                                    |
| `refusal`          | P0 ‡     | `refusal`   | The response is a deliberate refusal.                                    |
| `message.end`      | P0       | `message`   | Terminal. The complete, authoritative assistant message.                 |
| `error`            | P0       | `error`     | Terminal. The response failed.                                           |

† Required when the model uses a tool. ‡ Required when refusing.

**Grammar**

```text
stream   := message.start  body*  terminal
body     := status | retrieval | message.delta | citation
          | tool_call.start | tool_call.result | refusal
terminal := message.end | error
```

**Ordering constraints** (**MUST** unless stated otherwise)

- `message.start` is first. It **SHOULD** arrive within 1 s of the request, _before_ embedding, so the UI can react immediately.
- `retrieval` is sent **at most once**. It precedes every `citation` event and every `message.delta` that contains a citation marker, and **SHOULD** precede the first `message.delta`.
- Every `tool_call.start` is followed by **exactly one** `tool_call.result` with the same `tool_call.id`, before the terminal event. v1 tool calls are sequential and never overlap.
- `refusal` is sent **at most once**. If present: no `tool_call.*` events, and `message.end` has `finish_reason: "refusal"`.
- The concatenation of all `message.delta.delta` values **SHOULD** equal `message.end.message.content`. If you post-process (e.g. strip an invalid marker), `message.end` wins and the client swaps in the final text.


| `message_id`      | string   | P0                       |

| `created_at`      | datetime | P0                       |

#### `status` (P2)

```json

```

`phase` is one of `embedding` · `retrieving` · `filtering` · `calling_tool` · `generating`. `label` (P2) is optional
human-readable copy. Without status events the client shows a generic "thinking" state until the first content event.

#### `retrieval`

```json
{ "type": "retrieval", "retrieval": { "…": "see §2" } }
```

#### `message.delta`

```json

```

Arbitrary fragment. Markdown syntax and citation markers **may be split across deltas**, and the client handles that.

#### `citation` (P2)

```json
{ "type": "citation", "rank": 1, "chunk_id": "chk_delivery-tracking_01" }
```

Emit this when a complete `[n]` marker first appears in the generated text. It lets the inspector light up
"used in answer" live. Without it, the client derives usage from markers and reconciles on `message.end`.

#### `tool_call.start`

| -------------------------- | ------- | ---------------------------- |
| `tool_call.id`             | string  | P0                           |
| `tool_call.name`           | string  | P0                           |
| `tool_call.arguments`      | object  | P0                           |
| `tool_call.content_offset` | int ≥ 0 | P1. See [§3](#3-tool-calls). |

#### `tool_call.result`

```json

```

#### `refusal`

```json
{ "type": "refusal", "refusal": { "…": "see §4" } }
```

#### `message.end`

```json
{ "type": "message.end", "message": { "…": "AssistantMessage" } }
```

This is also exactly what the client persists per turn.

| ----------------- | --------------------------------- | ------------ | -------------------------------------------------------------------------------------------------------------------------------------------- |

| `conversation_id` | string                            | P0           |                                                                                                                                              |

#### `error`

```json
{
  "type": "error",
  "error": {
    "code": "upstream_unavailable",
    "message": "Groq is rate-limiting and the Ollama fallback did not respond.",
    "retryable": true,
    "request_id": "req_91ab"
  }
}
```

No `message.end` follows. If deltas were already sent, the client keeps the partial text and marks the message as failed with a retry affordance.

### 1.6 Citation markers

- The model sees the context chunks numbered by `rank` and cites them as `[n]`.
- `[n]` refers to `retrieval.chunks[]` with `rank == n`. Only chunks with `passed_threshold: true` go into the prompt, so only those can be cited.
- Multiple citations are written as adjacent markers: `[1][3]`. The server **SHOULD** normalise `[1, 3]` to `[1][3]` in the final `content`.
- Markers referencing a non-existent or non-qualifying rank: the server **SHOULD** strip them from the final `content`. The client renders them as plain text.
- In `message.end`, `retrieval.chunks[].used_in_answer` **MUST** be `true` for exactly the ranks that appear as markers in the final `content`, and `false` otherwise. A regex over the final text is sufficient.

## 2. Retrieval & source chunks

### `Retrieval`

| Field              | Type                       | Priority | Notes                                                                                                                                                                                      |
| ------------------ | -------------------------- | -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `query`            | string                     | P0       | The user's message as received.                                                                                                                                                            |
| `standalone_query` | string \| null             | P2       | The rewritten query actually embedded, if rewriting happened.                                                                                                                              |
| `top_k`            | int ≥ 1                    | P0       |                                                                                                                                                                                            |
| `distance_metric`  | `"cosine" \| "l2" \| "ip"` | P0       | Tells the client how to draw the distance scale.                                                                                                                                           |
| `threshold`        | number                     | P0       | A chunk qualifies iff `distance <= threshold`.                                                                                                                                             |
| `embedding_model`  | string                     | P1       | e.g. `all-MiniLM-L6-v2`                                                                                                                                                                    |
| `collection`       | string                     | P2       | Chroma collection name.                                                                                                                                                                    |
| `chunks`           | `SourceChunk[]`            | P0       | **Every** candidate the vector store returned, sorted by `rank` ascending, **including non-qualifying ones**. The inspector's threshold visualisation depends on seeing what was rejected. |

### `SourceChunk`

| Field              | Type             | Priority | Notes                                                                          |
| ------------------ | ---------------- | -------- | ------------------------------------------------------------------------------ |
| `id`               | string           | P0       | Chroma id.                                                                     |
| `rank`             | int ≥ 1          | P0       | 1 = closest. Citation markers reference this.                                  |
| `distance`         | number           | P0       | Raw distance from the vector store. **Lower is more similar.**                 |
| `passed_threshold` | boolean          | P0       | Computed server-side. The client never re-derives it.                          |
| `used_in_answer`   | boolean          | P0       | Always `false` in the `retrieval` event. Final value in `message.end`.         |
| `text`             | string           | P0       | Full chunk text as embedded, max 4000 chars. The source panel shows all of it. |
| `document`         | `SourceDocument` | P0       |                                                                                |
| `chunk_index`      | int ≥ 0          | P2       | Position within the document.                                                  |
| `token_count`      | int              | P2       |                                                                                |

### `SourceDocument`

| Field            | Type                        | Priority | Notes                                         |
| ---------------- | --------------------------- | -------- | --------------------------------------------- |
| `id`             | string                      | P0       | Stable per source document.                   |
| `title`          | string                      | P0       | e.g. "Late Delivery Compensation"             |
| `section`        | string \| null              | P1       | Heading the chunk falls under.                |
| `category`       | string \| null              | P2       | e.g. `refunds`, `delivery`, `safety`          |
| `source_path`    | string \| null              | P2       | e.g. `policies/late-delivery-compensation.md` |
| `version`        | string \| null              | P2       | e.g. `v2.1`                                   |
| `effective_date` | date (`YYYY-MM-DD`) \| null | P2       |                                               |

### Distance semantics

| Metric   | Chroma `hnsw:space`     | Range     | Meaning               |
| -------- | ----------------------- | --------- | --------------------- |
| `cosine` | `cosine`                | 0 – 2     | 1 − cosine similarity |
| `l2`     | `l2` _(Chroma default)_ | 0 – ∞     | squared Euclidean     |
| `ip`     | `ip`                    | unbounded | 1 − dot product       |

**Recommendation:** create the collection with `metadata={"hnsw:space": "cosine"}`. A fixed refusal threshold on
Chroma's default squared-L2 is much harder to reason about and to explain in an interview.

| `name`           | string                    | P0           |                                                                                                                                                                                                                                                        |
| `arguments`      | object                    | P0           | Parsed JSON, not a string.                                                                                                                                                                                                                             |

## 4. Refusals

A refusal is a **successful response**, not an error. It arrives as HTTP `200` and ends with `message.end`, never `error`.

**When:** no retrieved chunk passes the distance threshold _and_ the question isn't answered by a tool.

**How:** the server **SHOULD** skip the LLM entirely and return templated content. That makes it deterministic, costs nothing, and
removes any hallucination risk. `metadata.latency_ms.generation` is then `0` and `usage` is `null`.

**Event sequence**

```text
message.start → status* → retrieval (every chunk passed_threshold=false)
→ refusal → message.delta* (optional) → message.end (finish_reason="refusal")
```

### `Refusal`, discriminated on `reason`

**`reason: "below_threshold"`** (P0)

| Field             | Type                       | Priority     | Notes                                                                                                      |
| ----------------- | -------------------------- | ------------ | ---------------------------------------------------------------------------------------------------------- |
| `reason`          | `"below_threshold"`        | P0           |                                                                                                            |
| `message`         | string                     | P0           | Human-readable refusal copy.                                                                               |
| `threshold`       | number                     | P0           | Same value as `retrieval.threshold`.                                                                       |
| `distance_metric` | `"cosine" \| "l2" \| "ip"` | P0           |                                                                                                            |
| `closest_match`   | `SourceChunk \| null`      | P0, nullable | The rank-1 chunk that still failed. `null` only if the collection returned nothing.                        |
| `suggestions`     | string[]                   | P1           | 2–4 in-scope questions, ideally drawn from the nearest documents. The client falls back to a curated list. |

**`reason: "out_of_scope" | "unsafe"`** (P2, reserved for a future classifier or guardrail)

| Field         | Type                         | Priority |
| ------------- | ---------------------------- | -------- |
| `reason`      | `"out_of_scope" \| "unsafe"` | P2       |
| `message`     | string                       | P2       |
| `suggestions` | string[] \| null             | P2       |

`message.end.message.refusal` repeats the same object.

**Rules**

- **Timing.** Measure with a monotonic clock (`time.perf_counter()`). Floats are fine.
- **Waterfall.** With `spans`, the inspector draws a true waterfall, so generation → tool → generation is visible. Without them it lays out the `latency_ms` phases sequentially.
- **Trace links.** The server knows the Langfuse host and project id, so it should send `trace_url`. If only `trace_id` arrives, the client builds `${NEXT_PUBLIC_LANGFUSE_PROJECT_URL}/traces/${trace_id}` when that env var is set. Otherwise it shows the id with a copy button. Langfuse traces are private by default: mark the traces you want reviewers to open as public.
- **Suggested Langfuse mapping.**
  - Trace name `chat`, with `session_id = conversation_id`.
  - Trace metadata `{user_message_id, regenerate_of}`.
  - Child spans named as above; the LLM calls as `generation` observations carrying `usage`.

## 12. Minimum viable backend (P0 only)

Implement this first. The frontend is fully functional against it, with the inspector showing retrieval only.

1. `POST /chat` streams SSE with the framing in §1.4.
2. It emits `message.start` → `retrieval` → `message.delta`* → `message.end`, or a terminal `error`.
3. `retrieval.chunks` contains all top-k candidates with `rank`, `distance`, `passed_threshold`, `text`, and `document.{id,title}`.
4. `used_in_answer` in `message.end` matches the `[n]` markers in the final content.
5. When nothing passes the threshold, it emits `refusal` with `below_threshold`, `threshold`, `distance_metric`, and `closest_match`.
6. `lookup_order` emits `tool_call.start` + `tool_call.result`, with the P0 `LookupOrderResult` fields.
7. `GET /health` returns `status`, `checked_at`, `models.primary`, and `vector_store.{provider, available, document_count}`.
8. Pre-stream errors use the envelope in §5.

**Then P1:** `metadata` (trace_id, model, params, usage, latency_ms), `content_offset`, `history[].tool_calls`, `suggestions`, `section`.

**Then P2:** `status` events, `citation` events, `spans`, `standalone_query`, `/documents`, `/feedback`.

## 13. Implementation notes for FastAPI (non-normative)

```python
from fastapi.responses import StreamingResponse

SSE_HEADERS = {
    "Cache-Control": "no-cache, no-transform",
    "X-Accel-Buffering": "no",
}

def sse(seq: int, event: BaseModel) -> str:
    # model_dump_json() emits one line; newlines inside strings are escaped.
    return f"event: {event.type}\nid: {seq}\ndata: {event.model_dump_json()}\n\n"

@app.post("/chat")
async def chat(req: ChatRequest, request: Request):
    async def gen():
        seq = 0
        async for event in pipeline.run(req):          # yields Pydantic event models
            if await request.is_disconnected():
                break                                  # client pressed stop
            yield sse(seq, event)
            seq += 1
    return StreamingResponse(gen(), media_type="text/event-stream", headers=SSE_HEADERS)
```

- The JSON Schemas in `docs/contract/` can seed Pydantic models: `datamodel-codegen --input docs/contract/chat-stream-event.schema.json --input-file-type jsonschema`.
- Don't add `GZipMiddleware` globally, or exclude `text/event-stream` from it.
- Use a heartbeat task (or `sse-starlette`'s `ping=10`) if generation can go quiet for over 10 s.
